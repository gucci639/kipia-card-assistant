# AI-помощник для подготовки товарных описаний (КИПиА / B2B)

Прототип веб-сервиса и CLI-утилиты для автоматизированной подготовки черновиков карточек контрольно-измерительных приборов (КИПиА) для B2B-интернет-магазина с жёсткой защитой от галлюцинаций и прямой интеграцией с YML-фидом каталога **«Союз-Прибор»** (`https://www.souz-pribor.ru/yml/any/feed.xml`).

## 1. Возможности сервиса

- **Два режима ввода данных в веб-интерфейсе и API:**
  - Интерактивная **веб-форма** (построчное редактирование названия, производителя, характеристик и текста техпаспорта) и режим **Raw JSON**.
  - **Прямой импорт из YML-фида `souz-pribor.ru`** по ID предложения (`205776`, `54079`), артикулу, названию или прямому URL карточки товара с автоматическим обогащением таблицей характеристик и текстом паспорта.
- **Генерация всех требуемых блоков карточки B2B-товара:**
  1. `seo_title` — SEO-заголовок строго **до 70 символов** (с автоматическим контролем длины).
  2. `seo_description` — технически выверенное B2B SEO-описание объёмом **800–1 200 символов**.
  3. `structured_specs` — структурированный список ключевых характеристик, где отсутствующие параметры явно помечены как **`«данных нет»`**.
  4. `search_queries` — **3–5 целевых поисковых запросов** под коммерческий и инженерный интент.
  5. `commercial_block` — блок для менеджера по продажам: целевая аудитория (роли ЛПР/ЛВПР), решаемые инженерные задачи и аргументы для коммерческого предложения (КП).
  6. `completeness` — отчёт о полноте входных данных (скор `0..100%`), перечень отсутствующих полей и список уточняющих вопросов для контент-менеджера.
- **Экспорт в 1 клик:** переключение между вкладками **Карточка (UI)**, **Markdown**, **JSON** и **Plain Text** с кнопкой копирования в буфер обмена.
- **Устойчивость и безопасность:**
  - API-ключ вынесен в `.env` (шаблон в `.env.example`), поддержка любого OpenAI-совместимого провайдера (OpenAI, OpenRouter, Google Gemini, локальная Ollama).
  - Корректная обработка ошибок LLM API (`401`, `429`, `502`, `504`), битого JSON (`422`) и пустых полей.

### Ключевые решения при работе с YML-фидом `souz-pribor.ru`
При анализе реального YML-фида `https://www.souz-pribor.ru/yml/any/feed.xml` (~37 МБ, 47 982 товара) выяснилось два важных факта:
1. Внутри XML-узлов `<offer>` у большинства позиций передаются только `name`, `typePrefix`, `vendor`, `price`, `url` и два сервисных параметра (`Артикул` и `Код товара`), а тег `<description>` отсутствует.
2. При этом по ссылке `<url>` из каждого оффера доступна карточка товара с блоками `.characteristics__item`, `#specifications` и выдержкой из техпаспорта.

Поэтому в модуле `app/feed_importer.py` реализовано **двухступенчатое чтение**:
- Потоковый XML-парсер (`xml.etree.ElementTree.iterparse`) находит нужный оффер в 37-мегабайтном фиде за доли секунды без загрузки всего дерева в ОЗУ.
- При включённом флаге `enrich_from_web=True` сервис автоматически подтягивает таблицу характеристик и текст техпаспорта со страницы товара `<url>`, а при `enrich_from_web=False` позволяет протестировать поведение системы на «скудных» сырых данных из YML-фида.

## 3. Дизайн промптов и защита от галлюцинаций

В B2B-сегменте КИПиА выдуманный класс точности, диапазон давления или степень защиты IP может привести к закупке неподходящего прибора на промышленный объект. Поэтому мы не полагаемся только на «честное слово» LLM, а используем **трёхступенчатый контур контроля**:

1. **Предварительный детерминированный аудит (`analyze_input_completeness`):**
   - До вызова LLM код проверяет заполненность `name`, `manufacturer`, `description`, `specs` и наличие 5 базовых инженерных групп КИПиА (*диапазон измерений, класс точности, питание, тип корпуса/защита, интерфейсы/присоединение*).
   - Список реально отсутствующих групп передаётся прямо в `user_prompt` как явное ограничение: *«предварительный анализатор обнаружил нехватку следующих данных: ... Обязательно отрази их как "данных нет", НЕ выдумывай их значения!»*.
2. **Системный промпт (`SYSTEM_PROMPT`) + низкая температура (`0.2`) + JSON Mode:**
   - Задаёт роль технического редактора КИПиА, запрещает рекламные штампы и любые внешние допущения (ГОСТы, номера Госреестра, межповерочные интервалы, если их нет во входе).
   - Требует строгого соблюдения структуры 3 абзацев в `seo_description` (назначение -> характеристики -> монтаж и эксплуатация) и лимитов длины (`<= 70` и `800–1200` символов).
3. **Пост-процессинг и цикл самокоррекции (`merge_and_verify_specs`, `detect_unverified_numbers`):**
   - **Численный анти-галлюцинационный фильтр:** функция `detect_unverified_numbers` извлекает все числовые номиналы из сгенерированного `seo_description` и сверяет их с числами во входном JSON. Если LLM добавила число, которого не было во входе, или вышла за рамки `800–1200` символов, запускается корректирующий запрос (`build_length_correction_prompt`) с требованием удалить непроверенные цифры и привести длину к норме.
   - **Защита таблицы характеристик:** функция `merge_and_verify_specs` берёт за основу точные пары ключ-значение из входного `specs`, отбрасывает любые предложенные моделью характеристики с неподтверждёнными числами и принудительно проставляет `"данных нет"` для всех отсутствующих базовых категорий КИПиА.

## 4. Установка и быстрый запуск

### Шаг 1. Клонирование и создание виртуального окружения

```bash
git clone https://github.com/gucci639/kipia-card-assistant.git
cd kipia-card-assistant

python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

*(Если вы используете `uv`: `uv venv --seed .venv && source .venv/bin/activate && uv pip install -r requirements.txt`)*

### Шаг 2. Настройка API-ключа

Скопируйте шаблон `.env.example` в `.env` и укажите ваш ключ и модель:

```bash
cp .env.example .env
```

Пример содержимого `.env`:
```ini
LLM_API_KEY=sk-...
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4o-mini
LLM_TEMPERATURE=0.2
```
*(Поддерживаются OpenAI, OpenRouter, Google Gemini OpenAI-compatible endpoint, а также локальная Ollama по адресу `http://localhost:11434/v1`).*

### Шаг 3. Запуск веб-интерфейса (FastAPI)

```bash
uvicorn app.main:app --reload --port 8000
```

Откройте в браузере: **http://127.0.0.1:8000**

В веб-интерфейсе доступны:
- выпадающий список с предзагруженными товарами из YML-фида «Союз-Прибор» и ТЗ;
- поле прямого импорта любого оффера из `https://www.souz-pribor.ru/yml/any/feed.xml` по его ID (например, `205776` или `54079`) или URL;
- переключение между веб-формой и Raw JSON;
- мгновенное копирование результата в форматах Markdown, JSON или текста.

### Шаг 4. Запуск через CLI (командную строку)

Пакетная генерация карточек для всех демонстрационных товаров с сохранением в `data/examples_output/`:
```bash
python cli.py -i data/sample_inputs.json -o data/examples_output
```

Генерация карточки напрямую по ID товара из YML-фида «Союз-Прибор» с выводом Markdown в консоль:
```bash
python cli.py --yml-id 205776 -f markdown
```

### Шаг 5. Запуск автотестов

```bash
pytest -v
```

## 6. Ограничения текущего решения и план развития (Roadmap)

### Ограничения текущего прототипа
1. **Отсутствие OCR для PDF-паспортов:** сейчас сервис принимает текстовую выдержку из паспорта или парсит HTML-страницу товара. Если техпаспорт доступен только в виде отсканированного PDF-файла или чертежа, потребуется предварительное распознавание.
2. **Синхронная обработка одиночных карточек в UI:** при пакетной генерации сотен позиций из YML-фида (47+ тыс. офферов) последовательные HTTP-запросы упрутся в Rate Limit LLM-провайдера.
3. **Эвристический контроль чисел:** детектор `detect_unverified_numbers` проверяет совпадение всех числовых номиналов с исходным текстом, но не строит полную графовую онтологию единиц измерения (например, не переводит `1,6 МПа` в `16 кгс/см²` автоматически).

### Возможные улучшения для Production
1. **Интеграция с PDF-паспортами и Госреестром СИ (ФИФ ОЕИ «Аршин»):**
   - Автоматическое извлечение таблиц из PDF-руководств по эксплуатации (через `pypdf`/`Docling` или Vision-модели) и проверка актуальности свидетельства об утверждении типа СИ по номеру Госреестра.
2. **Асинхронная очередь пакетной генерации каталога (Celery / ARQ + Redis):**
   - Фоновая обработка всего YML-фида `souz-pribor.ru` с дедупликацией типоразмеров (например, линейки манометров, отличающихся только верхним пределом давления `0..1`, `0..10`, `0..100 кгс/см²`), что сократит расход токенов LLM в 8–10 раз.
3. **Интеграция с PIM / 1С-Битрикс:**
   - Прямая выгрузка утверждённого контент-менеджером черновика в инфоблоки 1С-Битрикс по REST API с автоматическим заполнением `META TITLE`, `META DESCRIPTION` и смарт-фильтров характеристик.
